# AI Strength Coach

Telegram-бот силовой и взрывной подготовки с учётом бокса. Он общается обычным
русским языком, хранит историю тренировок, назначает текущие подходы и адаптирует
нагрузку по результатам. Вымышленной личности у бота нет.

## Что уже работает

- живой диалог через LLM, включая опечатки и неверную раскладку;
- онбординг, профиль, цели, расписание бокса и ограничения;
- сохранение исходных рабочих подходов;
- предложения версионированной программы и её активация после подтверждения;
- вся тренировка одним сообщением: упражнения, точные подходы, повторы, вес и отдых;
- один итоговый отчёт после тренировки с сохранением каждого фактического подхода;
- корректировка следующих тренировок по повторениям в запасе, технике, боли и качеству взрывной работы;
- предложения добавить, заменить или убрать упражнение с научным обоснованием и активацией только после подтверждения;
- полугодовой прогноз силы диапазоном после накопления сопоставимых тренировок, с пометкой о высокой неопределённости по одной исходной записи;
- пример самой объёмной недели для конкретного упражнения: прямые рабочие подходы отдельно от разминки и вариаций, с разбивкой по интенсивности, повторам и тоннажу и со снижением перед тяжёлыми спаррингами;
- распределение тяжёлых упражнений по неделе с учётом общей усталости тренировки, пересечения нагрузки на хват, спину и корпус и приоритета главного движения;
- детерминированная коррекция программы: взрывная работа переносится в начало, дополнительные тяжёлые базовые движения облегчаются, а короткий день при трёх тренировках по боксу ограничивается восемью рабочими подходами;
- каталог популярных упражнений с исходной оценкой общей нагрузки и отметками нагрузки на хват, плечи, ноги, корпус и заднюю цепь;
- проверка совместимости с боксом учитывает не только усталость, но и амплитуду движений, скоростную практику, болезненность, массу тела и возможный дисбаланс объёма; упражнение не объявляется «вредным» без контекста дозировки и техники;
- SQLite-память с восстановлением незавершённой тренировки;
- расчёты Epley, Brzycki, RIR-e1RM, тоннажа и недельной session-RPE нагрузки;
- отдельный учёт массы тела и добавленного веса в подтягиваниях;
- журнал бокса и других занятий;
- научная база с реальными ссылками и ограничениями применимости;
- защита от повторно доставленных Telegram-сообщений;
- локальный CLI для проверки без Telegram;
- работа без сторонних Python-библиотек.

LLM принимает тренировочные решения и ведёт разговор. Детерминированное ядро
перепроверяет вес, шаг прогрессии и стоп-условия. Оно не позволяет повысить вес
после боли или ухудшения техники и не назначает рабочий вес без подтверждённой
исходной точки.

## Настройка локально

Требуется Python 3.11 или новее.

1. Скопировать `.env.example` в `.env`.
2. Заполнить один LLM-провайдер:
   - `GROQ_API_KEY` и при необходимости `GROQ_MODEL`; либо
   - `DEEPSEEK_API_KEY` и `DEEPSEEK_MODEL`; либо
   - универсальные `LLM_API_URL`, `LLM_API_KEY`, `LLM_MODEL`.
3. Для Telegram заполнить `TELEGRAM_BOT_TOKEN`.
4. В `TELEGRAM_ALLOWED_USER_IDS` указать разрешённые Telegram ID через запятую.
   Если список пуст, бот отвечает только в личных чатах.

Проверка в консоли Windows:

```powershell
py -m unittest discover -s tests -v
py -m coachbot.cli
```

Запуск Telegram:

```powershell
py run.py
```

## Развёртывание на Bothost

1. Создать для проекта отдельный публичный или подключённый приватный GitHub-репозиторий.
2. Загрузить содержимое этой папки в корень репозитория.
3. В Bothost выбрать сборку через `Dockerfile`.
4. Добавить переменные окружения:

```text
TELEGRAM_BOT_TOKEN=...
TELEGRAM_ALLOWED_USER_IDS=...
GROQ_API_KEY=...
GROQ_MODEL=qwen/qwen3.8-27b
DATA_DIR=/app/data
```

5. Подключить постоянное хранилище к `/app/data`. Без постоянного тома база
   тренировок исчезнет при пересоздании контейнера.
6. Запустить контейнер и написать боту `/start`.

Секреты нельзя добавлять в GitHub. Файл `.env` уже исключён через `.gitignore`.

Текст сообщений, профиль и релевантная история тренировок передаются выбранному
LLM-провайдеру для формирования ответа. Не указывайте лишние медицинские или иные
чувствительные данные; для полностью локального режима понадобится совместимый
локальный OpenAI API endpoint.

## Пример разговора

```text
Пользователь: Хочу добавить две силовые к трём тренировкам по боксу.
Бот: Уточни массу тела, опыт, оборудование, дни бокса и последние рабочие
     подходы в основных упражнениях.

Пользователь: 83 кг. Вчера жал 90 на 6, оставалось примерно 2 чистых повтора.
Бот: Зафиксировал исходный подход. Перед первой тренировкой уточним сон,
     усталость и сегодняшнюю боль, затем я дам весь план целиком.

Пользователь: Всё выполнил. В жиме 3×6 по 90 кг, оставалось около 2 повторов,
              техника нормальная, боли нет. Тренировка 55 минут, тяжесть 7/10.
Бот: Тренировка сохранена. Следующую нагрузку скорректирую по этому результату.
```

## Хранение данных

База находится в `DATA_DIR/coach.sqlite3`. В ней хранятся:

- профиль и исходные показатели;
- версии программы;
- планы и фактические тренировки;
- подходы, внутренняя числовая оценка повторов в запасе, техника, боль и масса тела;
- рекомендации LLM и итог проверки движком;
- история сообщений и идентификаторы событий.

Исходные подходы не пересчитываются задним числом. Производная аналитика строится
при формировании контекста и может быть обновлена без потери первичных данных.

## Границы безопасности

Бот не ставит диагнозы, не назначает лечение и не заменяет врача или очного
тренера. При боли или тревожных симптомах силовое упражнение останавливается.
Для предварительного скрининга используется ссылка на официальный
[PAR-Q+](https://eparmedx.com/), а не изменённая копия анкеты.
